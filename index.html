统计规则　数据源 %LOCALAPPDATA%\hermes\profiles\*\state.db 的 session_model_usage 表，读的是真实 API 回执，非估算。
含缓存 = input + output + cache_read + cache_write；reasoning tokens 已包含在 output 内，不重复叠加。
日维度只算「当天开、当天结」的会话（真实量、不虚高）。跨天常驻会话（first_seen≠last_seen）的累计不摊进任何单日，只在下方全期总量与按 Agent 排名里体现——因为它的逐日增量底层库根本不存在，强行拆分只会造假。所以看「今天烧多少」请认准今天视图（已剔除跨天），跨天会话请去全期/按 Agent 看。
真账校准：本地库 session_model_usage 只存「会话累计总量」、无按天增量，所以跨天常驻会话（小F/小畅/小重等跑好几天的 Agent）的当日消耗本地无法拆分——这是早前"今天"和官方对不上的根因，不是 bug。
三种口径并列：①官方平台日账（official_daily.jsonl，从平台用量页录入的权威当日真值：费用/请求/token）单日视图头条直接采用，与平台对账；②本地增量口径（usage_increments.jsonl，每天快照每个会话累计值、与基线比对得出真增量，午夜对齐自然日）从第二天起自动精确，含跨天会话当日部分；③same_day 下限（仅当天开当天结）是增量数据未覆盖时的回退。余额接口只给当前余额、不给逐日消费，故"当日真账"由各日余额差自动生成（午夜为主、04:00 兜底）。
单会话已 300 条消息零压缩，单次调用要读 19 万 token 上下文，这才是长会话 Agent 贵的真正原因。
金额按 1 美元 = 7.2 元折算，只用来给数额一个体感；真实账单以美元为准，汇率变了这里是近似值。
